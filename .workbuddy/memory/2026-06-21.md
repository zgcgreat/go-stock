## 修复登录页触发大量业务 API 请求

### 问题
Vue Router 守卫异步执行期间，默认路由 `/` 的 stock.vue 已被挂载，
onBeforeMount/onMounted 立即触发 7+N 个 API 请求。30+ 组件都有此问题。

### 修复：`frontend/src/services/api.js`
在 axios 请求拦截器中统一拦截：Web 模式下无 token 时，
非公开路由请求直接短路返回 `axios.Cancel`，不发 HTTP 请求。
- 公开 API（`/public/`、`/auth/`）不受影响
- 所有组件无需单独加 token 检查，一层拦截全部解决
- 原先在 stock.vue 和 WebLayout.vue 加的单独 token 检查已撤回

## AI 菜单审查 + 三项修复

### 分析结论
AI 菜单是**上游原有功能**（非 Web 端新增），但 Web 端实现有 3 个问题。

### P0: agentMode 参数丢失 (BUG)
- **根因**: `wails-bridge.js` ChatWithAgent 只映射 6 参数到 JSON body，第 7 参数 agentMode 被丢弃
- **影响**: 用户选择"快速"/"规划"模式实际走 auto，UI 选了白选
- **修复**:
  1. `wails-bridge.js` — 加 arg7 参数 + body.agentMode 字段

### P1: enableAgent 配置控制缺失
- **根因**: Web 端 AI 菜单始终显示，无视 enableAgent 配置
- **修复**: `WebLayout.vue` — 读取 GetConfig().enableAgent，控制 AI 菜单可见性

### P2: 会话持久化
- **根因**: agent-chat.vue 对话刷新即丢失，后端已有 session API 但前端未接入
- **修复**: `agent-chat.vue` — 接入 SaveAiAssistantSession/GetAiAssistantSession：

  - onBeforeUnmount 保存当前会话

## 修复 enableAgent/enableFund 保存后刷新还原

### 问题
设置页 enableAgent 开关保存后刷新页面，值还原为 false。

### 根因
`backend/data/settings_api.go:351-352` — `GetSettingConfigByUserID()` 返回前强制：
```go
settings.EnableFund = false
settings.EnableAgent = false
```
不管数据库实际值，读取时都被覆盖为 false。这是上游桌面端逻辑（Wails 通过其他方式控制开关），但 Web 端依赖此 API 返回值。

### 修复
删除两行强制覆盖，保留数据库实际值。同时恢复 settings.vue 中被注释的 enableAgent 开关。

### 额外修复
- `settings.vue` — 取消注释 AI智能体开关（enableAgent n-switch）
- `WebLayout.vue` — enableAgent 默认值改为 false，与后端一致

## 修复设置保存成功但显示红叉

### 问题
设置页保存配置，后端实际成功，但前端显示红色错误提示。

### 根因
- 后端 `UpdateAppConfig` 成功返回 `{"message": "配置更新成功"}`
- `wails-bridge.js` 提取 `res.data?.message` → `"配置更新成功"`
- 前端判断 `res === '保存成功！'` → 不匹配 → 走 `message.error()` 分支

### 修复
`settings.vue` 兼容两种返回值：桌面端 `"保存成功！"` + Web端 `"配置更新成功"`
