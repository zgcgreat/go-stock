## 修复市场情绪强弱 NaN 问题

**问题**：Web 端"市场情绪强弱"仪表盘显示 NaN

**根因**：
- 后端 `/market/hot-words` 返回格式：`{ code: 0, msg: "success", data: { result: { Score, ... }, frequencies: [...] } }`
- 前端 `wails-bridge.js` 中 `AnalyzeSentimentWithFreqWeight` 用 `apiData.data || apiData` 取数据层，当 `apiData.code === 0` 但 `apiData.data` 存在时逻辑正确，但旧代码用 `d.result || d` 作为 resultData —— 若 `d.result` 为 undefined，则 resultData 退化为含 `code/msg/data` 的整个对象，其 `Score` 字段不存在，乘以 10 得 NaN
- 组件中 `res.result.Score * 10` 无 null-safety 检查

**修复**：
1. `wails-bridge.js`：用 `apiData.code === 0 ? apiData.data : apiData` 精确提取层级；对 `result` 做 `typeof Score === 'number'` 检查，失败时返回安全默认值
2. `AnalyzeMartket.vue`：gauge data value 改用 `Number(res.result?.Score) || 0`；tooltip formatter 中 `value.toFixed` 改为 `(Number(value) || 0).toFixed(2)`；函数入口加 `if (!res || !res.frequencies) return` 防护

## 修复市场情绪强弱 Score 始终为 0 的根因

**根因**：`GetHotWords` 接口调用 `NewsAnalyze("", true)`，后者从本地 SQLite 查 24 小时内新闻。Web 端没有主动爬取，DB 为空，直接返回 Score=0。
**桌面端**：用户触发 RefreshTelegraphList 爬取后 DB 有数据，因此正常。
**修复**：`internal/handlers/web_handler.go` 的 `GetHotWords` 改为先调用 `TelegraphList(30)` + `GetSinaNews(30)` 主动爬取，再调用 `NewsAnalyze`，与 `RefreshTelegraphList` 保持一致。
