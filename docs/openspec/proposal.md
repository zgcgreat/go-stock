# Proposal: Web 端响应式菜单布局优化

## Problem Statement

当前 Web 端菜单固定在底部，使用水平模式（`mode="horizontal"`）。这种设计在桌面端尚可接受，但在手机端存在以下问题：

1. **菜单项过多**：当前有 7 个一级菜单，部分还有子菜单，在手机屏幕上显示拥挤
2. **底部菜单遮挡内容**：固定在底部的菜单栏占用屏幕空间，且容易与手机系统导航栏冲突
3. **子菜单难以操作**：水平菜单的子菜单在手机端展开不便
4. **不符合移动端习惯**：主流 App 在手机端通常使用底部 Tab 栏（4-5 个主要入口）或侧滑抽屉菜单

## Proposed Solution

采用**响应式布局**策略：

### 桌面端（宽度 >= 768px）
- 左侧固定侧边栏菜单
- 可折叠/展开，节省空间
- 支持子菜单展开

### 移动端（宽度 < 768px）
- 底部 Tab 栏显示 4-5 个主要入口
- 更多功能入口通过侧滑抽屉或弹出菜单访问
- 符合移动端用户习惯

## Goals

1. 改善移动端用户体验
2. 保持桌面端功能完整性
3. 尽量不改动原始桌面端代码
4. 使用 Naive UI 原生组件实现

## Non-Goals

1. 不修改桌面端（Wails）的菜单布局
2. 不添加新的菜单项
3. 不改变现有的路由结构

## Success Criteria

1. 移动端菜单操作流畅，符合用户习惯
2. 桌面端菜单功能与现有保持一致
3. 响应式切换平滑无闪烁
4. 构建通过，无运行时错误
